# F06b — Keep scalar metadata out of page-bearing template contexts

Navigation extracts the native taxonomy permalink before assigning a template variable. Atom computes native taxonomy URLs once per used kind per feed, then retains only scalar URLs. Term lookup similarly projects its slug before assignment. This branch deliberately leaves the default term page retrieval in place so F06a is independently measurable.

No taxonomy routes are hand-constructed. Native taxonomy lookup semantics, including the existing default-language behavior and required failures, remain in use. This replaces the audit's site-specific diagnostic URL construction with a general native-lookup approach.

The differential harness covers ordinary/fallback navigation, unused kinds, Unicode names, safe slugs and multilingual output. Full-corpus results were 363.278s baseline, 140.523s this branch alone, and 15.819s combined with F06a. All three candidates preserved the 6,131-file set: 6,116 byte-identical and 15 feeds equivalent ignoring only category ordering/formatting whitespace. The measurement is this host/corpus, not a universal timing guarantee.

The two independent branches touch the same Atom line; combining requires keeping F06b's scalar projection and adding F06a's `include_pages=false` to that lookup. Keep the differential output test as the acceptance gate, not the exact wall-clock number.
